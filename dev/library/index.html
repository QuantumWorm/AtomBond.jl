Structure library and element data

Structure library

File → Structure library… (Ctrl+L, also Build → From library…) lists known crystals and molecules with their formula, symmetry, cell and source (database entry and paper); Open loads one in a new tab. The structure is Untitled until saved, so Save never writes into the library. In code: structure_library, load_library (by name or formula), open_library!.

Finding a structure: Show picks crystals, molecules or both; Group narrows the list to one group; Search keeps the structures whose name, formula, group or use contain all the words typed (ethane, WF6, halide, etch, precursor).

Molecules are grouped the way chemistry textbooks classify them: first organic (carbon compounds), organometallic (metal–carbon bonds) or inorganic, then by functional group or type of compound. Within a group they are in alphabetical order.

Molecules used in semiconductor processing also say what for (Used as): etch gas, dopant source, deposition precursor, ALD/CVD co-reactant (oxidant, nitrogen source) or solvent. Search finds them by that too.

  • Crystals are CIFs from the Crystallography Open Database, stored as downloaded.
  • III–V semiconductors come from one review at 300 K instead, because COD's III–V entries are mostly old tables and some are off.
  • Molecules are experimental gas-phase geometries: the bond lengths and angles of the cited papers and books (each value read in the authors' own text, never taken from a data compilation), from which scripts/molecules.jl computes the coordinates. Each entry gives its point group and references; a few carry a note where the structure is approximate. They open in a non-periodic box with 5 Å of space; the library's Molecules: in a periodic cubic box switch makes the box periodic for plane-wave codes.
  • Radicals are open-shell species (surface adsorbates, plasma and CVD intermediates); their note gives the spin state to use.
  • Graphene and nanotubes are periodic only along some directions (extended XYZ with pbc): graphene in-plane, a nanotube along its axis (c), with vacuum elsewhere. Nanotubes are ideal rolled sheets, so relax them before use.
  • SiGe: the real alloy is random; the library holds the ordered model (Si and Ge on the two diamond sublattices) at the measured alloy lattice constant.

The library is data/library/library.toml with crystals/ and molecules/ beside it; scripts/build_library.jl downloads the COD files and rebuilds it, with the molecules from scripts/molecules.jl. Your own structures go into ~/.atombond/library/library.toml (or $ATOMBOND_HOME/library/), in the same format with the files next to it (category sets the group; an optional use is shown and searched).

Element data

All element data is in one table, data/elements.csv (Z 1–103), generated by scripts/build_element_table.jl from the published sources:

ColumnUsed forSource
massQE and LAMMPS massesNIST Atomic Weights and Isotopic Compositions (IUPAC/CIAAW standard atomic weights)
covalent_radiusbonds, ball sizeCordero et al., Dalton Trans. 2008, 2832
vdw_radius_bondiCPK sizeBondi, J. Phys. Chem. 68, 441 (1964), with Mantina et al. 2009
vdw_radius_alvarezCPK size where Bondi has noneAlvarez, Dalton Trans. 42, 8617 (2013)
color_jmolatom coloursJmol element colours (H white, C grey, N blue, O red, …)

element(:Si) gives an Element; element_property(:Si, :vdw_radius_alvarez) reads any column.

Your own values: put an elements.csv with the same layout in ~/.atombond/ (or $ATOMBOND_HOME), with only the columns and rows to change:

symbol,color,vdw_radius
O,FF2020,1.40
Si,1B3BFA,

color and vdw_radius take precedence over the built-in columns, and new columns become readable with element_property. use_vesta_colors! takes the colours (and optionally the radii) from a VESTA elements.ini.
