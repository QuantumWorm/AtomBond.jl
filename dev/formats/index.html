File formats

load_structure and save_structure choose the format from the file name.

Code / programReadWrite

GeneralCIF (symmetry expanded), XYZ / extended XYZ, PDB (CRYST1)CIF (P1), extended XYZ, PDB
  • A .in file is read as pw.x, FHI-aims or ABINIT input depending on its contents.
  • Files without a cell (XYZ, PDB without CRYST1, a molecule XSF, aims without lattice vectors) are put in a box with 5 Å of space and treated as molecules (not periodic). The box is drawn dashed.
  • CIF: partial occupancies are drawn as full atoms, with a warning.
  • Examples of each format are in examples/structures/formats. They are written by hand in each program's documented layout, not output of the programs themselves.

The separate input writers for DFT codes (with k-points and constraints) are described in DFT inputs and constraints. to_atomsbase and from_atomsbase convert to and from AtomsBase systems, which packages such as DFTK accept.
