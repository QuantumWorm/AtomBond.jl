API: running calculations

Running DFT calculations from AtomBond, with DFTK.jl or another engine, and reading their results (see DFT inputs and constraints and DFT engines). The plots of the results are under Rendering and window.

AtomBond.DFTEngine — Type
DFTEngine

A code AtomBond can run. An engine is a (usually empty) struct with methods for engine_id, engine_name, write_engine_inputs and read_engine_results, and optionally engine_executables, engine_command, engine_tasks, engine_finished, engine_history, engine_pseudo_default and engine_install_hint; register_engine! adds it to the Run tool. See Adding a DFT engine in the manual for a template.

The settings file of the engines: $ATOMBOND_ENGINES when set, otherwise atombond/engines.toml in $XDG_CONFIG_HOME (default ~/.config). One table per engine id:

AtomBond.find_engine — Method
find_engine(e) -> (; command, source, found) or nothing

The command that runs engine e, from the first of: the command in the settings file (engine_settings_file), the environment variable ATOMBOND_<ID>_COMMAND (e.g. ATOMBOND_CASTEP_COMMAND="mpirun -np 4 castep.mpi"), or the PATH (engine_executables, e.g. castep in ~/bin). command is split into words like a shell would; found tells whether its program exists. nothing when none of these gives a command.

AtomBond.run_dft — Method
run_dft(c; engine=:dftk, dir, name, kspacing=0.25, ecutwfc=40, pseudo, relax=:auto, bands=false, command) -> DFTJob

Start a calculation of c with a DFT engine in the background (dft_engines): writes the inputs into dir (default: a new folder <engine>_<name>_<time>), runs the program there with its output in name.log, and returns the job (job_status, job_results, stop_job!). relax as in run_dftk: :none, :atoms, :cell, or :auto (relax when c has constraints). command overrides the one find_engine finds. With engine=:dftk this is run_dftk (which also does bands).

set_engine_setting!(e, key, value)

Store a setting of an engine (e.g. "command", "pseudo_dir") in the settings file, keeping the others; nothing removes it.

AtomBond.write_engine_inputs — Function
write_engine_inputs(e, dir, name, c; relax, kspacing, ecutwfc, pseudo) -> (input, output)

Write the input files of a calculation of c into dir (they exist). relax is :none (an SCF), :atoms or :cell; ecutwfc is in Ry, kspacing in 1/Å (2π included, see kpoint_grid); pseudo is the text of the tool's Pseudopotentials field. Returns the main input file and the file that exists once the calculation has finished (its results).

AtomBond.BandPath — Type
BandPath

Band structure along the high-symmetry path: distances along the path (1/Å, 2π included), branch_starts (index where each continuous piece starts; the path jumps between pieces), tick positions ticks with their labels (e.g. "Γ", "X", "U | K" at a jump) and eigenvalues[σ][k, band] (eV) per spin.

source
AtomBond.ConvergenceResults — Type
ConvergenceResults

A convergence check read by read_convergence: natoms, the SCF steps (ConvergenceStep) of the "cutoff" and "kpoints" series, planned (all steps of the run; fewer are present while it runs) and the DFTK version.

source
AtomBond.ConvergenceStep — Type

One SCF of a convergence check: cutoff (Ry), k-spacing (1/Å), k-grid, energy (eV), gap (eV) or nothing.

source

DFTJob

A DFTK calculation started by run_dftk (or the DFTK installation started by install_dftk): the process, its folder, script, log and results files, and the structure it was started from.

source
AtomBond.DFTKJob — Type

The name DFTJob had before AtomBond ran other codes than DFTK.

AtomBond.DFTKResults — Type

The name DFTResults had before AtomBond ran other codes than DFTK.

source
AtomBond.DFTResults — Type
DFTResults

What a finished DFTK run reports (from <name>.results.toml). Energies in eV (energy, terms, fermi, homo, lumo; nothing where not known), forces in eV/Å per atom, structure the final structure (the relaxed one after a relaxation), calculation "scf" or "relax", converged, iterations (SCF iterations or relaxation steps) and, for an SCF, eigenvalues (eV, per k-point and spin), occupations and kweights. With the extra non-self-consistent step (run_dftk(…; bands=true)): dense, the levels on a denser k-grid (DenseLevels), and path, the band structure along the high-symmetry path (BandPath); nothing otherwise. After a relaxation, history holds every step (RelaxHistory); with bands=true the levels (and dense, path) are those of an SCF of the relaxed structure.

source
AtomBond.DFTResults — Method
DFTResults(; calculation, converged, energy, structure, kw...)

Results with only some of the fields known (what an engine's output gives): the rest default to empty (no levels, no forces, no history).

source
AtomBond.DenseLevels — Type
DenseLevels

Levels (eV) of a non-self-consistent run on a denser Γ-centred k-grid kgrid: eigenvalues per irreducible k-point (spin up first, then spin down), with kweights summing to 1 per spin. dos uses them when present.

source
AtomBond.OrbitalWeights — Type
OrbitalWeights

Projections of the states on the pseudo-atomic orbitals (orthonormalized, as DFTK's atomic_orbital_projections), summed over m: for each (atom, orbital) group g — atoms[g], species[g], orbitals[g] (the pseudopotential's label, e.g. "3S") — weights[k][band, g], for the levels levels (:dense or :scf) of the same results. What the orbitals do not capture (the spilling) is missing from their sum. pdos uses them.

source
AtomBond.RelaxHistory — Type
RelaxHistory

The steps of a relaxation: energies (eV), the largest force on an atom that may move (max_forces, eV/Å; clamped atoms keep their forces and are left out), the structure of each step (structures) and the force on every atom (forces, eV/Å), and which atoms were clamped. When the cell was relaxed too, stresses holds the stress tensor of each step (GPa, positive = tensile: the cell would shrink; empty for a fixed cell); see pressure and cell_change.

source
AtomBond.band_edges — Method
band_edges(r) -> (; vbm, cbm, gap, direct, vbm_at, cbm_at, source) or nothing

Valence-band maximum and conduction-band minimum (eV): the highest level below the Fermi level and the lowest above it, over every k-point the run computed (SCF grid, dense grid, band path). With a band path, direct says whether both lie at the same point of the path and vbm_at/cbm_at where ("Γ", "between Γ and X", …); otherwise those are nothing. source says which levels were available. nothing for a metal (is_metallic) or without levels above or below the Fermi level.

source
AtomBond.band_gap — Method

Band gap in eV (band_edges: over all computed k-points), or nothing when it is not known or the levels are partly filled (is_metallic). On a k-grid alone it can be larger than the true gap; the band path finds the edges between grid points.

source
AtomBond.cell_change — Function
cell_change(h::RelaxHistory, k=length(h)) -> NamedTuple

How the cell of step k differs from the start: volume and a, b, c in percent, the angles α, β, γ in degrees, and the lattice parameters before and after (Å and degrees).

source
AtomBond.converged_settings — Method
converged_settings(cr; tol=1.0) -> (; ecut, kspacing)

The smallest cutoff (Ry) and the largest k-spacing (1/Å) whose total energy, and that of every more accurate step of the series, is within tol meV per atom of the most accurate one; nothing for a series that is missing or not converged within its range (only its most accurate step qualifies).

source
AtomBond.default_dftk_env — Method
default_dftk_env() -> String

The Julia environment AtomBond runs DFTK in: environments/atombond-dftk in the first depot (e.g. ~/.julia/environments/atombond-dftk), shared by all AtomBond sessions. install_dftk creates it.

source
AtomBond.dftk_cutoff_hints — Method
dftk_cutoff_hints(elements; family=DFTK_PSEUDO_FAMILY, env=default_dftk_env()) -> Dict

The kinetic-energy cutoffs (Ha) the pseudopotential family recommends for each element, element => (; low, normal, high) (PseudoDojo publishes these three levels; families with a single value give it for all three). They come from PseudoPotentialData in the DFTK environment, read by a short helper process (which downloads the family the first time), and are kept for the session. Elements the family lacks, or a family without hints (e.g. a {El} file pattern), are left out.

source
AtomBond.dftk_env_ready — Function

Whether env is an environment with DFTK and the other packages the scripts need.

source
AtomBond.dos — Method
dos(r::DFTResults; width=0.1, step=width/10, range=nothing) -> (; energies, dos, fermi)

Density of states from the levels of an SCF, each broadened into a Gaussian of standard deviation width (eV) and weighted with its k-point weight: dos[i, σ] is in states per eV per cell for spin σ (one column without spin polarization, where each level holds two electrons; spin up and down otherwise), at energies[i] (eV, absolute; fermi is the Fermi level). By default the energies cover all computed levels with 4 widths to spare.

The levels are those of the denser k-grid (DenseLevels) when the run computed them (levels=:dense, the default :auto), which also include more empty bands; otherwise (:scf) those of the SCF, whose few empty bands make the DOS stop a little above the Fermi level.

source
AtomBond.install_dftk — Function
install_dftk(env=default_dftk_env()) -> DFTJob

Create the DFTK environment (adds DFTK, PseudoPotentialData, AtomsBase, Unitful, UnitfulAtomic and GeometryOptimization, and precompiles them) in a separate process. It downloads and compiles a lot, so it takes several minutes the first time; job_status says when it is done and the log shows the progress.

source
AtomBond.is_metallic — Method
is_metallic(r; tol=0.003) -> Bool

Whether the levels make a metal: some band (the n-th level of each k-point, per spin) lies above the Fermi level at one k-point and below it at another (more than tol eV away; as DFTK's is_metal, over the SCF and the dense k-grid), or an SCF level within tol of the Fermi level is partly filled (e.g. a molecule's half-filled level). Partly filled levels alone are not enough: with smearing, the Fermi level of an insulator can sit at the top of the valence band and leave it slightly empty (GaAs at Γ).

source
AtomBond.pdos — Method
pdos(r; by=:element_orbital, atoms=nothing, width=0.1, step=width/10, range=nothing) -> (; energies, curves, fermi)

Projected density of states: as dos, but each level weighted with its projection on the atomic orbitals (OrbitalWeights) and summed into curves by by — :element ("Si", "O"), :orbital ("s", "p", "d"), :element_orbital ("Si 3s", "O 2p"), :atom ("Si1") or :atom_orbital ("O17 2p") — optionally only for the atoms numbered in atoms. curves is a vector of name => matrix (energy × spin, states/eV per cell), in the order of first appearance. The curves add up to a little less than the DOS (the spilling of the projections).

The pressure −tr(σ)/3 of a stress tensor σ (GPa): positive when the cell would expand.

AtomBond.read_dftk_results — Method
read_dftk_results(path; title="") -> DFTResults

Read the results file written by a DFTK script from write_dftk with results=… (as run_dftk does), and the band file next to it (<name>.bands.toml) when there is one. homo and lumo are the highest SCF level below the Fermi level and the lowest above it.

source
AtomBond.recommended_ecut — Method
recommended_ecut(c; precision=:normal, family, env) -> cutoff in Ry, or nothing

The cutoff for c: the largest recommendation (dftk_cutoff_hints) among its elements at precision (:low, :normal or :high), in Ry (twice the Ha value, as the tools and ecutwfc use Ry). nothing when there are no hints for some element.

source
AtomBond.run_dftk — Method
run_dftk(c; dir, name, env=default_dftk_env(), kspacing=0.25, ecutwfc=40, pseudo, relax=:auto) -> DFTJob

Start a DFTK calculation of c in the background: writes name.jl (see write_dftk: an SCF, or a relaxation when c has constraints; relax=:atoms or :cell asks for a relaxation of the atoms, or of the atoms and the cell, :none for an SCF) into dir and runs it with Julia in env, logging to name.log. When it finishes, name.results.toml holds the results (job_results). dir defaults to a new folder dftk_<name>_<time> under the current folder. With bands=true an SCF is followed by a non-self-consistent step: the levels on a k-grid twice as dense (a fuller DOS) and, for a crystal without vacuum, the band structure along the high-symmetry path, in name.bands.toml (read_dftk_results reads it too). With symmetrize (default: when bands) the atoms are first put on exactly symmetric positions (symmetrize, within 0.001 Å), so that DFTK and the k-path code, whose symmetry tolerance is much tighter, see the crystal's full symmetry (CIF coordinates are often rounded); also the default for a cell relaxation, where it keeps the stress exactly symmetric.

source
AtomBond.run_dftk_convergence — Method
run_dftk_convergence(c; ecuts=auto, kspacings=auto, ecutwfc=auto, kspacing=0.25, dir, name, env, pseudo) -> DFTJob

Start a convergence check of c in DFTK (script from write_dftk_convergence): SCF total energies for a series of cutoffs (by default around the cutoff the pseudopotentials recommend, recommended_ecut, from half to 1.5 times it) at the k-grid of kspacing, and for a series of k-spacings (one per distinct k-grid; none for a molecule) at the cutoff ecutwfc (default: the recommended one, or 40 Ry). The results go to name.convergence.toml; read them with job_convergence or read_convergence.
